KV Cache（鍵值快取機制）

大型語言模型自回歸（Autoregressive）推論加速的核心基石：透過快取歷史 Token 的 Key 與 Value 向量，避免重複計算。

1. 為什麼需要 KV Cache？

在基於 Transformer 的解碼器生成文字時，模型每次只會預測下一個 Token。若不使用快取，每生成一個新 Token 都必須重新計算前面所有 Token 的 Q、K、V 矩陣，導致計算量隨序列長度呈平方級成長。

2. 運作階段拆解

推論階段 主要行為 效能瓶頸
Prefill（預填充） 平行處理整段 Prompt，計算並儲存所有輸入 Token 的 K 與 V 矩陣。 計算密集型（Compute-bound）
Decode（逐字生成） 僅計算當前新 Token 的 Q、K、V，並與快取中的歷史 K、V 拼接進行注意力運算。 記憶體頻寬密集型（Memory-bandwidth bound）

3. 衍生演進方向

隨著上下文長度擴展至 128K 甚至百萬等級，KV Cache 佔用的 GPU 顯存成為主要瓶頸，進而催生了 MQA（Multi-Query Attention）、GQA（Grouped-Query Attention）以及 DeepSeek-R1 所採用的 MLA（Multi-Head Latent Attention）壓縮技術。
